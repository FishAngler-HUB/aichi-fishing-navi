# 釣果データの自動取得（Google Drive + rclone）設定手順

Google Drive の「釣り情報」フォルダにある最新の
`aichi-fishing-report-YYYYMMDD.md` を毎朝取り込み、
`data/catches.json`（今日のおすすめ釣り場の「釣果実績」）を更新する設定です。

処理の流れ：

```
Google Drive「釣り情報」
  → 最新の aichi-fishing-report-*.md を rclone で取得（読み取り専用）
  → data/reports/ に保存
  → tools/parse-report.js で解析
  → data/catches.json を更新（.tmp→検証→置換、直前版は .bak）
```

> Git への commit / push は自動では行いません。公開サイトへ反映したいときは
> `data/catches.json` を自分で commit / push してください。

---

## 1. rclone を用意する（1回だけ）

1. https://rclone.org/downloads/ を開く
2. **「Windows - AMD64 - 64 Bit」** の zip をダウンロード
3. zip を展開し、中の **`rclone.exe` だけ** を取り出す
4. `rclone.exe` を次の場所に置く：

   ```
   釣り場おすすめ情報ツール\tools\rclone.exe
   ```

   （このプロジェクトの `tools` フォルダ。管理者権限は不要です。
   　`.gitignore` で除外済みなので Git には入りません）

---

## 2. Google Drive につなぐ（1回だけ・ブラウザ認証）

コマンドプロンプトを開き、プロジェクトフォルダへ移動してから設定ウィザードを起動します。

```
cd /d "パス\釣り場おすすめ情報ツール"
tools\rclone.exe config
```

聞かれたら次のように答えます（`→` の右が入力）。

| 質問 | 入力 |
| --- | --- |
| `e/n/d/r/c/s/q>` | `n`（新規） |
| `name>` | `gdrive` |
| `Storage>` | `drive`（一覧の "Google Drive" の番号でも可） |
| `client_id>` | （何も入れず Enter） |
| `client_secret>` | （何も入れず Enter） |
| `scope>` | **`drive.readonly` の番号**（通常は `2`）。＝**読み取り専用** |
| `service_account_file>` | （何も入れず Enter） |
| `Edit advanced config?` | `n` |
| `Use auto config?` | `y` → ブラウザが開く → Google にログイン → 「許可」 |
| `Configure this as a Shared Drive (Team Drive)?` | **`n`**（このフォルダは自分のマイドライブ内） |
| `Keep this "gdrive" remote?` | `y` |
| 最後 | `q` で終了 |

- 認証情報（アクセストークン）は Windows の
  `%APPDATA%\rclone\rclone.conf` に保存されます（**プロジェクトの外**なので Git には入りません）。
- パスワードはどこにも保存されません（ブラウザ認証のみ）。

### つながったか確認

```
tools\rclone.exe lsf gdrive: --include "aichi-fishing-report-*.md" -R
```

`aichi-fishing-report-20260830.md` のようなファイル名が表示されればOKです。
「釣り情報」がサブフォルダになっている場合は、次のように出ます：

```
釣り情報/aichi-fishing-report-20260830.md
```

---

## 3. 設定ファイル `tools/.env` を作る（1回だけ）

`tools` フォルダに **`.env`** という名前のテキストファイルを新規作成し、次を記入します
（`.env` は `.gitignore` で除外済みなので Git には入りません）。

```
RCLONE_EXE=tools\rclone.exe
RCLONE_REMOTE=gdrive
RCLONE_PATH=釣り情報
```

- `RCLONE_PATH` は「釣り情報」フォルダの名前です。
  手順2の確認で `aichi-fishing-report-*.md` がフォルダ無しで直接表示された場合は、
  `RCLONE_PATH=`（空）にしてください。

---

## 4. 手動テスト（タスク登録の前に必ず行う）

プロジェクトフォルダで：

```
npm run update:catches
```

または `tools\run-update-catches.bat` をダブルクリック。

期待する動作：

- 初回：Drive の最新 `.md` が `data\reports\` に保存され、`data\catches.json` が更新される
- 2回目以降で Drive に新しい日付が無いとき：
  「新しいレポートが無いため catches.json は据え置きました」と表示され、**何も変更されない**
- 結果は `tools\fetch.log` に追記されます

個別に試したいとき：

| コマンド | 動作 |
| --- | --- |
| `npm run fetch:report` | Drive から最新 `.md` を取得するところまで（catches.json は触らない） |
| `npm run parse:report` | `data\reports\` の最新 `.md` から `catches.json` を作り直す（Drive は見ない） |
| `npm run update:catches` | 取得 → 解析 → 検証 を一括（Windows 自動実行と同じ処理） |

---

## 5. うまくいかないときの確認場所

| 症状 | 確認すること |
| --- | --- |
| `rclone を実行できません` | `tools\rclone.exe` が置いてあるか。`tools\.env` の `RCLONE_EXE` |
| `Drive のフォルダ一覧を取得できませんでした` | `tools\rclone.exe lsf gdrive:` が通るか。`tools\.env` の `RCLONE_REMOTE` / `RCLONE_PATH` |
| `aichi-fishing-report-*.md が見つかりません` | Drive の「釣り情報」フォルダにファイルがあるか。`RCLONE_PATH` の綴り |
| `tools/.env が未設定です` | 手順3の `.env` を作成したか（場所は `tools` フォルダ直下） |
| `取得した Markdown がレポート形式ではありません` | Drive 上のファイルが壊れていないか（中身を開いて確認） |
| 何度実行しても更新されない | それが正常です。Drive に新しい日付のレポートが増えたときだけ更新されます |

`tools\fetch.log` に毎回の実行結果（成功／変更なし／エラー）が記録されます。

---

## 6. タスク スケジューラに登録する（手動テストが済んでから）

> ⚠️ 手順4の手動テストで「取得 → catches.json 更新」が確認できるまでは登録しないでください。

既存の「天気更新」タスク（6:00）はそのまま残します。**別の新しいタスク**を追加します。

### 1. タスク スケジューラを開く

- Windows キー → `タスク スケジューラ` と入力して開く

### 2. 新しいタスクを作る

- 右側の **「基本タスクの作成」**

### 3. 名前

- 名前：`釣り情報ツール 釣果更新`
- 「次へ」

### 4. いつ実行するか

- **「毎日」** →「次へ」
- 開始時刻：`6:05:00`
- 「次へ」

### 5. 何を実行するか

- **「プログラムの開始」** →「次へ」
- **「プログラム/スクリプト」** の「参照」で次を選ぶ：
  ```
  釣り場おすすめ情報ツール\tools\run-update-catches.bat
  ```
- 「引数の追加」「開始（オプション）」は **空のまま**
- 「次へ」→「完了」

### 6. 追加の設定（推奨・天気タスクと同じ）

- 作成したタスクを右クリック →「プロパティ」
- **「全般」タブ**
  - **「ユーザーがログオンしているときのみ実行する」を選ぶ**（パスワードは聞かれません）
  - 「最上位の特権で実行する」は **チェックなし**
- **「条件」タブ**
  - 「コンピューターをAC電源で使用している場合のみ…」のチェックを外す（任意）
- **「設定」タブ**
  - 「スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを開始する」にチェック
- 「OK」

### 7. 動作テスト

- 一覧でタスクを右クリック →「実行する」
- `tools\fetch.log` に新しい結果が追記されていれば成功

---

## 7. 公開サイトへの反映（手動）

`update:catches` は `data/catches.json` をローカルで更新するところまでです。
GitHub Pages のサイトに反映したいときは、プロジェクトフォルダで：

```
git add data/catches.json data/reports/
git commit -m "chore: update catches.json from latest report"
git push
```

（`data/reports/` の `.md` も一緒にコミットして、生成元を残す方針です）
